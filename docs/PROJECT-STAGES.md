# 阶段实施记录

## 文档目的

本项目最初分析 WorkBuddy 可行性时，将实施工作拆成两个阶段。本文件记录两个阶段各自解决的问题、完成内容、验收方式和最终结果，帮助后续维护者理解项目为何形成当前架构。

阶段划分与版本号并非完全等价。阶段一建立技术底座和最小可用主题，主要成果集中在 `0.1.0`。阶段二从 `0.1.0` 的体验修复继续推进，并在 `0.2.0` 到 `0.2.2` 完成主题系统和全场景验收闭环。

## 阶段一：可行性验证与最小可用实现

### 阶段目标

阶段一回答以下核心问题：

1. WorkBuddy 是否为 Electron 桌面应用，能否通过 CDP 访问渲染页面。
2. 能否在不修改官方安装文件的前提下应用 CSS 和图片主题。
3. 能否限制调试接口只在本机回环地址开放。
4. 能否可靠识别 WorkBuddy 页面，避免注入错误目标。
5. 页面刷新、导航和 WorkBuddy 重启后能否保持或重新应用皮肤。
6. 能否完整清理注入内容并恢复官方外观。
7. 方案是否具备继续扩展为可日常使用项目的基础。

### 已完成的技术验证

1. 确认 WorkBuddy `5.2.5` 使用 Electron `37` 渲染结构。
2. 确认 WorkBuddy 可以使用 `--remote-debugging-address` 和 `--remote-debugging-port` 启动本机 CDP。
3. 完成动态回环端口选择，避免固定端口冲突。
4. 完成监听地址检查，拒绝非回环监听。
5. 完成端口进程所有权检查，确保监听者是选定的 `WorkBuddy.exe`。
6. 完成本地文件协议页面筛选，以及标题、根节点和 WorkBuddy 结构二次探测。
7. 完成 Node.js CDP WebSocket 客户端，不引入 npm 依赖。
8. 完成渲染器内 CSS、主题元数据和装饰节点注入。
9. 完成页面加载事件和 DOM 变化后的重新应用。
10. 完成重复注入前清理，保证样式和装饰节点不重复叠加。
11. 完成渲染器清理函数、注入器停止和普通模式重启。

### 已完成的产品功能

1. 建立“深海夜航”默认主题。
2. 覆盖 WorkBuddy 首页、主内容区、侧栏、会话区和输入区的基础视觉。
3. 支持一张本地图片作为主题背景和主视觉。
4. 支持主色、背景色、面板色、高亮色、文字色和次级文字色调整。
5. 支持图片格式和大小校验。
6. 支持脚本启动、恢复和截图验证。
7. 支持安装到 `%LOCALAPPDATA%\WorkBuddyDreamSkin\app`。
8. 支持开始菜单与桌面快捷方式。
9. 兼容代理终端可能遗留的 `ELECTRON_RUN_AS_NODE` 环境变量。
10. 修复 PowerShell 严格模式下单进程结果集合展开问题。

### 阶段一验证体系

1. PowerShell 脚本语法解析。
2. Node.js 注入器语法检查。
3. 注入载荷离线组装检查。
4. WorkBuddy 页面探针。
5. 主题版本一致性检查。
6. 根节点、样式节点和装饰节点存在性检查。
7. 页面根节点可见性和横向溢出检查。
8. 截图留档。
9. 实机恢复官方外观验证。

### 阶段一结论

WorkBuddy 可以在不修改官方文件的条件下实现外置换肤。CDP 方案具备可逆性、端口边界、页面身份验证和热重载能力，足以作为长期实现基础。

阶段一交付的是安全可运行的最小闭环。此时核心技术问题已经解决，但页面覆盖、交互状态、设置中心和复杂任务场景仍需要系统优化，这些工作进入阶段二。

## 阶段二：全面体验优化与主题系统产品化

### 阶段目标

阶段二将可运行方案提升到可长期日常使用的质量，重点解决：

1. 浅色 WorkBuddy 页面中的白底、低对比文字和悬停失真。
2. 主导航之外的业务页面、弹窗、设置中心和任务状态覆盖不足。
3. 单张图片主题表达力有限，无法实现背景、主视觉和小装饰图组合。
4. 每次换图都要手工编辑，缺少可保存和可切换的主题资产。
5. 人工点击页面容易漏验，缺少真实悬停和全页面自动审计。

### 主界面和交互体验完成项

1. 修复聊天顶部栏、当前任务、加载骨架和选中项的对比度。
2. 修复任务卡片、更多入口、快捷操作和成长计划入口的白色悬停。
3. 修复输入区模型按钮、工作空间按钮和默认权限按钮的悬停可读性。
4. 修复模型列表、模型说明浮层和工具提示的浅色残留。
5. 修复日常办公、代码开发、设计创意三个场景的推荐标签和溢出渐变。
6. 修复侧栏当前入口、快捷按钮、查看更多、收起和空间标题的悬停状态。
7. 限制品牌装饰文字和人物装饰图只在欢迎页出现，避免遮挡会话和业务页面。
8. 修复任务准备状态的大面积白底和低对比状态文字。
9. 修复任务完成页面中的 Markdown 代码块、代码标题栏、表格和结果区域。
10. 保留键盘焦点和原生控件可操作性。

### 业务页面覆盖完成项

1. 完成新建任务首页覆盖。
2. 完成助理页面和快捷操作区覆盖。
3. 完成项目页面和新建项目弹窗覆盖。
4. 完成专家、技能和连接器页面覆盖。
5. 完成专家详情弹窗覆盖。
6. 完成自动化列表和自动化编辑器覆盖。
7. 完成更多菜单及其选中状态覆盖。
8. 完成腾讯文档授权页面覆盖。
9. 完成用户菜单、签到卡片、余额和操作入口覆盖。
10. 完成设置中心十一项页面逐项覆盖。

设置中心覆盖范围包括：

1. 账户管理。
2. 系统设置。
3. 智能体设置。
4. 快捷键。
5. 记忆。
6. 模型。
7. 助理设置。
8. 个性化。
9. 数据管理。
10. 安全中心。
11. 帮助与反馈。

设置专项处理了额度卡片、快捷键表格、键帽、记忆卡片、模型空状态、二维码绑定区、个性化输入框、数据管理条目和安全中心卡片。二维码图像保留扫描所需白底。

### 图片分层和主题系统完成项

1. 将单图主题升级为 Schema 2。
2. 增加 `background` 背景图角色。
3. 增加 `hero` 欢迎页主视觉角色。
4. 增加可选 `character` 人物卡或装饰图角色。
5. 支持三层图片分别设置位置和尺寸。
6. 支持背景遮罩、主视觉遮罩、装饰图透明度和面板透明度。
7. 兼容 Schema 1，并将旧单图映射到背景与主视觉。
8. 相同图片承担多个角色时只编码一次。
9. 热刷新时创建新 Blob URL 并撤销旧 URL，避免继续显示旧图和资源泄漏。
10. 完成主题预设保存、列表、应用和切换前自动备份。
11. 完成 `switch-workbuddy-theme.ps1` 单命令入口。
12. 完成拍立得 SVG 装饰卡生成器。
13. 建立 `deep-sea-layered`、`gilded-night-banquet` 和 `sunlit-campus` 三套预设。

### 阶段二自动化验收完成项

1. 悬停审计，覆盖会话卡片、更多入口、快捷操作、成长计划和侧栏展开收起。
2. 输入区审计，覆盖模型触发器、工作空间、权限、模型弹层和模型说明。
3. 场景审计，覆盖日常办公、代码开发、设计创意和推荐标签。
4. 页面审计，覆盖九个主要页面和通用容器。
5. 深层审计，覆盖专家详情、新建项目、自动化编辑器、更多菜单和腾讯文档授权。
6. 设置审计，覆盖十一项设置页面。
7. 通用验证增加 Markdown 代码块、代码标题栏、表格、任务内容区和任务准备页检查。
8. 所有页面检查大面积亮色表面、低对比叶子文本、浅色伪元素和横向溢出。
9. 审计脚本只执行安全导航，不发送消息，不保存设置，不创建项目，不执行授权。
10. 支持逐页面截图和结构化 JSON 结果。

### 阶段二结论

阶段二已经完成。项目从单一页面主题脚本发展为具备多页面兼容、真实交互审计、图片分层、主题预设管理和完整恢复能力的独立 WorkBuddy 换肤项目。

当前版本可以用于日常体验和继续迭代。后续工作的重点是跟随 WorkBuddy 版本变化维护兼容性、增加主题资产和提升自动化报告能力。

## 两个阶段的演进关系

| 对比维度 | 阶段一 | 阶段二 |
| --- | --- | --- |
| 核心问题 | 能否安全实现 | 能否长期好用 |
| 主题结构 | 单图和基础配色 | 三层图片、布局、效果和预设 |
| 页面范围 | 首页、侧栏、会话和输入区基础覆盖 | 主业务页面、弹窗、设置中心和任务状态全面覆盖 |
| 交互验证 | 基础结构和截图 | 真实悬停、浮层、场景和逐页面审计 |
| 恢复能力 | 完成 | 保持并纳入持续验收 |
| 用户操作 | 启动、恢复、基础自定义 | 一条命令切换、多主题保存、拍立得生成 |
| 项目状态 | 最小可用 | 独立可维护项目 |
